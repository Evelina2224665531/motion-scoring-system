# 动作打分系统初步方案

- 项目名称：动作打分系统（motion-scoring-system）
- 文档版本：v0.1
- 编写日期：2026-10-17
- 文档性质：技术路线与实施计划；尚未实施模型训练、代码开发或硬件性能测试。
- 开发路径：电脑摄像头验证 → 完整套路识别 → 香橙派 RK3566 部署 → 评分增强。

## 1. 项目目标与初期范围

### 1.1 必须完成

1. 在电脑上使用摄像头采集人体动作，检测人体关键点并计算相关角度。
2. 通过标准示范视频或实际录制的数据建立动作数据集。
3. 对约三分钟的固定动作套路进行连续识别，实时展示当前动作、动作阶段和完成进度。
4. 将推理与展示功能移植到采用 RK3566 的香橙派，尽量离线运行。

### 1.2 逐步增强

- 标准性：判断动作幅度、关键姿态和运动轨迹是否达到要求。
- 连贯性：判断非预期停顿、动作衔接和速度变化。
- 音乐配合：判断动作关键事件与指定音乐节拍的时间偏差。
- 结束报告：展示完成率、分项得分、主要问题和有效观测覆盖率。

### 1.3 初期假设

- 单人、单个普通 RGB 摄像头、固定套路、固定主要机位。
- 人体尽量完整出现在画面中，光照稳定，背景不复杂。
- 初期以肩、肘、腕、髋、膝、踝等大关节动作为主。
- 多人同时评分、精细手指动作、严重遮挡及可靠三维测量不属于第一阶段范围。

单摄像头得到的二维角度会随拍摄方向变化。多视角训练能够改善识别适应性，但不能保证恢复被遮挡关节的真实三维角度。对观测不足的动作应提示无法可靠判断，避免强行评分。

## 2. 总体技术架构

```text
摄像头 / 录像 + 采集时间戳
    ↓
人体姿态估计：关键点坐标 + 置信度
    ↓
坐标还原、缺失处理、平滑、身体尺度归一化
    ↓
关节角度 + 相对位置 + 速度 + 可见性特征
    ↓
动作识别与阶段判断
    ↓
套路状态机：当前动作实例、重复次数、遗漏与恢复
    ↓
实时界面、动作评分、结束报告

音乐播放时钟 + 指定节拍标注 → 音乐配合评分
```

区分三类工作：人体关键点检测先用预训练模型；动作识别使用项目自己的动作数据；质量评分使用明确规则，后续可加入人工评分数据训练。初期不从零训练人体姿态模型。

## 3. 两档实施方案

| 项目 | 基础版：优先跑通和移植 | 增强版：提升识别与评分 |
| --- | --- | --- |
| 主要输出 | 当前动作、阶段、完成次数和遗漏 | 基础版输出及标准性、连贯性、节奏分数 |
| 姿态估计 | YOLOv8n-pose 预训练模型 | 沿用基础模型，必要时场景微调 |
| 动作判断 | 规则、动作模板、受约束在线 DTW、状态机 | 小型因果 TCN、状态机和模板评分 |
| 训练需求 | 可不训练神经网络，主要建立模板和调参 | 训练骨架时序动作模型 |
| 适用条件 | 固定机位、固定套路、动作差异明显 | 更多人员、速度变化和一定范围的视角变化 |
| 主要限制 | 相似动作和视角变化容易引起混淆 | 数据及标注工作量增加，仍受遮挡影响 |
| 板端分工 | NPU 检测姿态，CPU 执行动作逻辑 | NPU 检测姿态，小型 TCN 先在 CPU 验证 |

推荐先完成基础版。两档方案共用关键点定义、数据格式和模块接口，增强版逐步替换动作判断模块。

Rockchip 官方模型库提供 RK3566 的 YOLOv8 Pose 部署示例。具体吞吐量、延迟和量化精度必须在实际板卡与系统上测试，不能仅凭模型支持列表推断。

## 4. 电脑开发环境与代码组织

### 4.1 开发环境

| 用途 | 初步选型 |
| --- | --- |
| 摄像头、算法和界面开发 | Windows 原生、Python 3.10、VS Code、venv |
| 图像采集与处理 | OpenCV |
| 数值计算和数据处理 | NumPy、SciPy、Pandas |
| 电脑端部署模型推理 | ONNX Runtime |
| 时序模型训练 | PyTorch；有合适的 NVIDIA 显卡时使用 CUDA |
| 初期显示 | OpenCV 窗口，后续按需求升级界面 |
| RKNN 转换 | 独立 Ubuntu 环境，安装匹配版本的 RKNN-Toolkit2 |
| 板端推理 | RKNN-Toolkit-Lite2 或 RKNN C/C++ Runtime |

Windows 摄像头调试与 Linux 模型转换分开，避免把摄像头访问问题和模型转换依赖混在一起。没有独立显卡也可先开发基础版；训练速度由实际电脑配置决定。

基础环境示例，在工程根目录执行：

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install opencv-python numpy scipy pandas onnxruntime scikit-learn
```

PyTorch 根据电脑显卡和官方安装说明单独安装。项目跑通后锁定依赖、模型和官方示例版本；板端依赖单独管理，不直接复制 Windows 虚拟环境。

以下为后续开发规划，目前仅创建“说明”目录和本文档。

```text
motion-scoring-system/

├─ configs/                 # 动作定义、阈值、套路和节拍配置

├─ models/                  # ONNX、RKNN 和时序模型

│  ├─ routine/              # 套路状态机
```

统一姿态接口：输入图像，输出原图坐标系中的 17 个关键点、置信度和采集时间戳。移植时更换推理后端，保留特征、动作和评分逻辑。

## 5. 数据准备

### 5.1 先定义动作清单

将套路拆成“动作类别—动作实例—动作阶段”。同一动作重复出现时要有不同的实例编号。

例如：下蹲包含站立、下蹲、最低点、起立、完成；平举包含准备、抬臂、到位、放下。每个动作定义关注关节、完成条件、合理时长、允许误差和对应音乐事件。

### 5.2 基础版采集建议

| 数据类型 | 起步规模 | 用途 |
| --- | --- | --- |
| 标准动作 | 3～5 人，每动作 5～10 次 | 模板和合理变化范围 |
| 完整套路 | 每人 3～5 套 | 验证动作过渡和累计误判 |
| 常见错误 | 每种错误 10～20 段 | 确定判断边界 |
| 非目标行为 | 站立、走动、整理衣服、停顿等 | 减少误识别 |

先固定主要机位，再补充倾斜方向。网上视频可辅助定义动作，但应补录与实际使用机位接近的示范。保留原视频，便于回看骨架提取错误。

### 5.3 增强版采集建议

第一轮可按“20 人 × 10 种动作 × 3 个视角 × 5 次”规划约 3000 个动作片段，并另录完整套路、停顿、漏做、错误动作和不同质量水平的数据。

上述数量是实验起点，不是准确率保证。根据独立测试结果补充容易混淆的动作、人员和场景。

### 5.4 数据格式与划分

- 视频标注：video_id、person_id、session_id、view、start_time、end_time、action_id、phase、error_type。
- 骨架序列：timestamp、17 点坐标、置信度、缺失掩码；离线保存为 NPZ 等格式。
- 质量标注：标准性、连贯性、节奏分数及评分人；依据统一评分规则。
- 音乐标注：音频版本、指定拍点时间、动作关键事件和对应关系。

按人员划分训练、验证和测试集，例如 14/3/3 人。相邻帧、同一次表演的不同机位必须放在同一集合。所有用于调阈值、训练和量化校准的数据应与最终测试数据分开。

## 6. 基础版算法执行步骤

1. 跑通摄像头和预训练姿态模型，显示骨架，保存视频与关键点。
2. 还原图像缩放和补边。计算角度时使用同一尺度的坐标，不能直接对宽高分别归一化的坐标计算。
3. 以髋部中心平移、以身体尺度归一化；加入关键点置信度、短时缺失处理和轻量平滑。
4. 提取关节角度、手腕相对肩部高度、脚踝间距和运动方向等特征。仅靠角度不足以区分所有动作。
5. 从标准示范建立分动作、分视角模板；对关键关节设置不同权重和容差。
6. 结合规则和短窗口在线 DTW 判断动作阶段，设置最短持续时间与状态切换条件，避免抖动误计数。
7. 状态机确认完整阶段后才计为完成。允许停顿、跳过和重新定位，不按音乐时间自动认定完成。
8. 用未参与调参的人员完成整套动作，检查漏计数、误计数、错误跳转和恢复能力。

关键点长期遮挡时暂停相关指标评分并提示调整位置；禁止用长时间插值伪造有效动作轨迹。

## 7. 增强版模型训练步骤

1. 使用部署路线一致的姿态模型离线提取骨架，人工抽查异常样本。
2. 按时间戳重采样，初始可采用 15 Hz；保留缺失掩码，避免把缺失当作零坐标。
3. 使用最近约 2 秒的特征窗口，训练小型因果 TCN；仅使用当前和过去数据，避免未来帧泄漏。
4. 输出当前动作类别和阶段，包含其他、过渡等类别，并设置低置信度拒识机制。
5. 起始配置：3～4 层时序卷积，Adam，学习率约 1e-3，先训练 50～100 轮，按验证集早停。
6. 使用动作分类损失和阶段分类损失；对少数类、过渡类评估并处理类别不均衡。
7. 可加入关键点噪声、短时丢点和适度速度变化。左右翻转要同步调整骨架及动作标签；节奏数据变速时必须同步音乐标注。
8. 在完整录像上评估动作分类、阶段边界、完成计数和延迟，不只报告剪辑片段准确率。
9. 导出 ONNX，验证与训练模型一致；板端优先试 CPU 推理，必要时再验证 RKNN 转换和算子支持。

输入窗口长度不等于额外等待同样时长，但启动时需要处理历史窗口不足的问题。动作识别阈值和稳定输出策略也会引入延迟，需要测量。

只有骨架检测误差成为主要瓶颈时，才微调姿态模型。此时需要人工校正人体框、关键点和可见性标注；动作类别或分数标签不能替代姿态标注。

## 8. 评分设计

| 分项 | 初步方法 | 注意事项 |
| --- | --- | --- |
| 标准性 | 按阶段比较角度、相对位置、最大幅度和轨迹 | 根据视角和动作设权重，区分体型差异 |
| 连贯性 | 比较非预期停顿、衔接时间和速度曲线 | 保留规定停顿与快速发力的合理性 |
| 音乐配合 | 比较动作关键事件与指定节拍的时间差 | 不只匹配最近节拍，防止错一拍仍得高分 |

初始质量分可试用：标准性 60% + 连贯性 20% + 音乐配合 20%。权重和分数映射需通过人工评价校准，不能把任意距离公式直接当成客观标准。

完成率和有效观测覆盖率单独显示。遗漏、跳过、长期遮挡的处理规则须提前定义，避免仅完成少数简单动作就获得高总评。

姿态比较可以进行受约束时间对齐；节奏评分保留原始时间关系，不能把快慢差异一起消除。音乐优先由系统播放，人工标记固定曲目的关键拍点，校准摄像头、音频输出和滤波延迟。

## 9. RK3566 移植步骤

1. 确认香橙派准确型号、内存、系统架构、Linux 镜像及 RKNPU 驱动。先验证摄像头出图和官方 NPU 示例。
2. 使用 Rockchip 官方 yolov8_pose 配套 ONNX 模型和后处理建立基准。其他来源的同名模型不能直接假设输出结构一致。
3. 在电脑 Ubuntu 环境安装兼容的 RKNN-Toolkit2，选择目标平台 rk3566。记录工具链、运行库、驱动和模型版本。
4. 从训练侧视频抽取约 200～500 张代表性图像，覆盖人员、姿态、光照、距离和遮挡，建立量化校准列表。该数量为起始建议。
5. 按锁定版本的官方脚本完成量化和转换。当前参考脚本提供两步混合量化流程；自定义模型需核对内部节点和参数。
6. 将 RKNN 模型和匹配的 Runtime / Lite2 部署到板端，依次验证单张图、固定视频、摄像头，再集成动作和界面。
7. 对同一测试视频比较电脑 ONNX 与板端 RKNN 的关键点偏差、动作结果、完成计数和评分变化。
8. 将姿态后端切换为 RKNN，角度计算、状态机和评分继续在 CPU 运行；增强版小型 TCN 根据实测决定部署位置。
9. 采集、推理和显示分开，队列保持有界并优先处理最新帧，避免延迟累积。按真实时间戳计算速度。
10. 测量各模块耗时，必要时降低输入分辨率、减少显示开销或将热点改为 C++。任何性能调整都重新验证识别精度。

当前参考脚本的命令示例，在官方 yolov8_pose/python 目录执行：

```bash
python convert.py ../model/yolov8n-pose.onnx rk3566 i8 1
python convert.py ../model/yolov8n-pose.onnx rk3566 i8 2
```

执行前需要完成依赖安装、模型下载和校准列表配置。脚本参数与模型节点可能随版本变化，应以锁定版本的代码为准。

板端不进行日常模型训练。Windows 的 Python 环境、CUDA 程序和 ONNX 文件不能直接视为已经可在 RK3566 NPU 上运行。

## 10. 开发里程碑与验收

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| M0：硬件验证 | 电脑摄像头、板端摄像头、官方 NPU 示例 | 能采集图像，板端能运行姿态示例 |
| M1：三个代表动作 | 关键点记录、角度显示、动作模板、计数 | 能识别动作阶段，干扰行为不会频繁计数 |
| M2：完整三分钟 | 套路配置、进度状态机、完整录像评估 | 能处理重复、停顿、漏做与恢复 |
| M3：基础版上板 | RKNN 推理、实时界面、性能记录 | 电脑与板端结果偏差可解释，无持续积压 |
| M4：评分增强 | 小型 TCN、分项评分、人工对比报告 | 未见人员上有效，分数与规则及人工评价相符 |

建议先完成 M0 和 M1，尽早暴露硬件与模型限制，再扩大数据采集。

初期性能目标：姿态更新 10～15 次/秒，界面反馈尽量在 200～300 ms 内；单次三分钟无持续积压，并连续运行至少 30 分钟检查温度和性能变化。这些是待验证目标，不是已测性能承诺。快速动作和精细节奏评分可能需要更高采样率。

评估记录包括：宏平均 F1、阶段边界误差、整套误计数和漏计数、反馈延迟、观测覆盖率、板端量化前后差异。具体质量门槛在动作清单确定后制定。

## 11. 下一步需要明确的信息

1. 动作种类、动作数量和标准示范视频；是否存在转身、跳跃、蹲地或复杂手部动作。
2. 音乐是否固定、动作顺序是否固定、能否由系统播放音乐。
3. 电脑 CPU、显卡、内存和摄像头规格。
4. 香橙派准确型号、内存、系统版本以及摄像头接口。
5. 可参与采集的人数、可接受的拍摄机位和最终展示方式。

下一步优先任务：选择三个代表动作，定义阶段与完成标准，搭建电脑骨架采集程序，同时验证板端官方姿态示例。
